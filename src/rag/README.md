# rag — 검색 및 Gemini 답변

담당: 이찬영. 안전장치, 검색, 프롬프트 조립, Gemini 호출, 대화 저장까지 구현했습니다.

**추가 패키지가 필요 없습니다.** `google-genai` 대신 표준 라이브러리 `urllib` 로 REST 를 부릅니다.
의존성을 늘리면 공통 설정 변경이라 팀과 먼저 공유해야 하는데, 그럴 필요가 없어졌습니다.

Gemini 를 실제로 부를 때만 `GEMINI_API_KEY` 가 필요합니다. 그 전 단계는 키 없이 확인됩니다.

실제 키로 `gemini-3.8-flash` 호출과 답변 수신까지 확인했습니다 (2026-09-12).

## 실행

VS Code 터미널(PowerShell)에서 저장소 루트 기준으로 실행합니다.
설치하지 않았다면 새 터미널마다 첫 줄을 한 번 실행합니다.

```powershell
$env:PYTHONPATH = "src"
python -m rag stats
python -m rag ask "상대 팀에 단일 대상 궁극기가 많은데 뭘 올려야 하나요?" --patch 26.18
python -m rag ask "계속 붙어서 싸우는데 핵심 룬 뭐 들죠?" --champion Garen --trade 지속
python -m rag ask "무한의 대검 언제 올려요?" --call --patch 26.18
python -m rag history
```

기본은 프롬프트까지만 만들고 멈춥니다. `--call` 을 주어야 Gemini 를 부릅니다.
`--show-prompt` 로 보낼 내용을 그대로 볼 수 있습니다.

대화는 기본으로 `data/conversations.db` 에 남습니다. 남기지 않으려면 `--no-save` 를 줍니다.

근거 자료로 쓰는 Data Dragon 의 필드별 형식과, 어떤 질문에 답할 수 있고 없는지는 [`DATA_DRAGON.md`](DATA_DRAGON.md) 에 정리했습니다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `guard.py` | 질문을 걸러 Gemini 를 부를지 정합니다 |
| `store.py` | 근거 문서를 읽고 검색 단위인 청크로 자릅니다 |
| `retrieve.py` | 질문에 맞는 청크를 찾고 출처를 모읍니다 |
| `prompt.py` | 근거에 문서 ID 와 출처를 붙여 프롬프트를 만듭니다 |
| `gemini.py` | Gemini REST 호출. 표준 라이브러리만 씁니다 |
| `conversation.py` | 대화를 SQLite 에 남깁니다 |
| `api.py` | 입구 `answer_question`. 다른 모듈은 이것만 씁니다 |
| `knowledge_source.py` | `knowledge.get_documents` 로 근거 자료를 받아 패치별로 한 번만 청크로 만듭니다 |
| `pipeline.py` | 위 단계를 이어 상태를 정합니다 |
| `__main__.py` | 결과를 눈으로 확인하는 도구입니다 |

## 입구: `answer_question`

`docs/interfaces.md` 의 초안을 따릅니다.

```text
rag.answer_question(질문, 패치, 선택적 분석 결과) -> 답변, 출처, 근거 부족 여부
```

```python
from rag import answer_question

result = answer_question('무한의 대검 언제 사?', '26.18')
result['answer']                 # 답변 문장. 모델을 부르지 않았거나 실패했으면 None
result['sources']                # 출처 목록 (doc_id, title, source_url, version)
result['insufficient_evidence']  # 근거 자료가 없어 답하지 않았으면 True
```

rag 가 하는 일과 하지 않는 일을 나눕니다.

| rag 가 함 | rag 가 하지 않음 |
|---|---|
| 안전장치, 청킹, 순위, 프롬프트, Gemini 호출, 대화 저장 | 자료 수집, DB 구조, 패치 번호와 Data Dragon 버전 대응 (knowledge) |
| `knowledge.get_documents` 로 근거 받기 | 라이엇 API 호출 (riot). 분석 결과는 호출하는 쪽이 넘깁니다 |

### 합의 전 가정과 임시로 정한 것

팀과 정해야 하는 항목이라 코드에도 같은 내용을 적어 두었습니다.

| 항목 | 지금 정한 것 |
|---|---|
| `get_documents(패치, 챔피언 또는 아이템)` 의 뜻 | **가정 B**: 종류로 읽습니다. `get_documents('26.18', 'item')` 은 그 패치의 아이템 문서 전체 |
| 받는 종류 | `item`, `champion` 에 더해 초안에 없는 `rune`, `patch` 도 받습니다 |
| 받는 문서 형식 | `tests/fixtures/rag/documents_ddragon.json` 의 문서 형식이라고 봅니다 |
| 호출 횟수 | 같은 패치는 한 번만 받아 둡니다. 실패하면 저장하지 않고 다음 질문에서 다시 받습니다 |
| 패치를 `None` 으로 부르면 | 최신 자료를 돌려준다고 봅니다 |
| 자료가 없는 패치의 롤 질문 판정 | 안전장치의 이름 목록만 최신 자료에서 가져옵니다. 그러지 않으면 "근거 부족" 이 "롤 질문 아님" 으로 바뀝니다 |
| 동기/비동기 | 동기 함수. 결과가 올 때까지 멈추며, Gemini 호출은 최악이면 186초입니다. 화면이 같은 흐름에서 부르면 그동안 멈춥니다 |
| 오류 표현 | 근거 받기와 모델 호출에서 난 오류만 `status`, `error` 로 돌려줍니다. 대화 저장 실패 등 그 밖의 오류는 예외로 나옵니다 |
| 초안에 없는 출력 | `status`, `reason`, `message`, `error`, `usage` |
| 분석 결과 모양 | `{'champion': 'Garen', 'playstyle': {'trade_preference': '지속', 'lane_aggression': '높음'}}` |

`knowledge.get_documents` 가 아직 없어서, 기본으로 부르면 `status` 가 `knowledge_error` 로 돌아옵니다.
테스트와 `python -m rag` 는 fixture 를 읽는 대역(`fixture_get_documents`)을 넣어서 씁니다.

```python
from rag import answer_question
from rag.knowledge_source import DocumentSource, fixture_get_documents

source = DocumentSource(fixture_get_documents())
result = answer_question('무한의 대검 언제 사?', '26.18', source=source)
```

## 상태 네 가지

`docs/interfaces.md` 의 "서로 구분한다" 를 따릅니다. 뭉뚱그리면 사용자에게 틀린 안내를 하게 됩니다.

| 상태 | 뜻 | Gemini |
|---|---|---|
| `off_topic` | 롤 질문이 아닙니다 | 부르지 않음 |
| `out_of_scope` | 롤이지만 협곡이 아닙니다 | 부르지 않음 |
| `insufficient_evidence` | 협곡 질문인데 자료가 없습니다 | 부르지 않음 |
| `ready` | 근거를 찾았습니다 | 부릅니다 |
| `model_error` | 호출이 실패했습니다 (키, 한도, 연결) | 부르려다 실패 |

"자료가 없다" 와 "다룰 주제가 아니다" 와 "우리 범위가 아니다" 는 서로 다릅니다.
날씨 질문에 "자료가 부족합니다" 라고 답하면 틀린 안내입니다.

## 안전장치

챗봇 규약의 토큰 낭비 방지 장치입니다. **검색과 생성보다 먼저** 실행해야 토큰을 아낍니다.

금지어 목록을 만들지 않습니다. 끝이 없기 때문입니다.
대신 **롤이라는 근거가 있을 때만 통과**시킵니다. 근거는 세 가지입니다.

1. 롤 용어 (`궁극기`, `라인전`, `패치`, `한타` …)
2. 낱말이 정확히 같은 짧은 용어 (`탑`, `정글`, `룬`, `cs` …)
3. 자료에 있는 이름 전체 (`무한의 대검`)

`대검` 처럼 이름의 **일부만** 겹치는 것은 근거로 보지 않습니다.
그러지 않으면 "대검 같은 칼 어디서 파나요" 가 통과합니다.

`이동 속도`, `방어력`, `체력`, `회복`, `피해` 는 일부러 용어 목록에서 뺐습니다.
롤 밖에서도 흔히 쓰는 말이라 "방어력 높은 자동차 추천" 이 통과하기 때문입니다.

모드 판정을 먼저 합니다. 칼바람 질문에도 롤 용어가 들어 있어서입니다.

## 청킹

패치 노트는 문서 하나가 16,000자가 넘어 프롬프트에 통째로 넣을 수 없습니다.

| `kind` | 자르는 방식 |
|---|---|
| `champion` | 패시브와 Q~R 을 한 줄씩 나눕니다 |
| `patch` | 400자 기준으로 모으되 줄 중간에서 자르지 않고, 앞 2줄을 겹칩니다 |
| `item`, `rune` | 짧아서 대개 한 덩어리입니다 |

줄 중간에서 자르지 않는 이유는 수치가 `방어력` / `: 34 + 레벨당 5 ⇒` / `32 + 레벨당 4.7` 처럼
여러 줄로 나뉘어 있어, 중간에서 끊으면 변경 전후가 갈라지기 때문입니다.
겹치는 이유는 `카시오페아` 다음 줄부터 수치가 나와, 겹치지 않으면 이름과 수치가 분리되기 때문입니다.

## 검색

형태소 분석기를 쓰지 않습니다. 의존성을 늘리지 않기 위해서입니다.

| 신호 | 점수 |
|---|---|
| 이름 일치 | 최대 5 (겹치는 비율만큼) |
| 상황 태그 일치 | 태그당 최대 4 (흔한 태그일수록 낮아짐) |
| 픽창 성향 태그 일치 | 태그당 4 |
| 챔피언 분류 태그 일치 | 태그당 3 |
| 챔피언 일치 | 3 |
| 본문 낱말 일치 | 낱말당 최대 2 (역빈도로 낮아짐) |
| 질문이 묻는 종류와 일치 | 2, 패치 변경을 묻는 질문의 패치 노트는 5 (다른 근거가 있을 때만) |

합계 2점 미만은 버립니다. 문서당 최대 2청크만 가져와 한 문서가 상위권을 독차지하지 못하게 합니다.

**이름 일치는 비율로 봅니다.** `무한의 대검` 질문에 `처형인의 대검` 이 같은 점수를 받던 문제 때문입니다.
이름 글자 중 질문에 나온 비율과, 질문 낱말 중 이름에 들어간 비율 가운데 큰 쪽을 씁니다.
`시미터` 처럼 줄여 불러도 걸립니다.

**이어 주는 말은 검색어에서 뺍니다.** 챔피언 173명을 넣자 `이번` 이 `아이번` 에 걸렸습니다.

**패치 변경 질문은 패치 노트를 크게 올립니다.** 챔피언과 아이템 문서는 지금 상태만 담고 있어
"뭐 바뀌었어" 에 답할 수 없는데, 챔피언 문서가 이름 일치로 패치 노트를 앞질렀습니다.

**역빈도**: `상대`, `피해` 처럼 거의 모든 문서에 나오는 낱말은 0 에 가까워집니다.
값을 0~1 로 맞춥니다. 그러지 않으면 낱말 하나가 이름 일치보다 큰 점수를 받는데,
아이템 설명에는 아이템 이름이 들어 있지 않아서 정답이 밀려납니다.

**종류 보너스는 다른 근거가 있을 때만** 줍니다. 그러지 않으면 "뭐 사요?" 한마디에 모든 아이템이 통과합니다.

## 한계

- **상황어 사전과 `situation_tags` 는 검증된 게임 지식이 아니라 RiftFlow 가 직접 적은 것입니다.**
  사전에 없는 표현은 걸리지 않습니다.
- 같은 태그를 가진 룬끼리는 순위가 갈리지 않습니다.
  정복자와 착취의 손아귀는 가렌에게 둘 다 말이 되는 선택이라 동점입니다.
  여기서 더 올리려면 태그를 테스트에 맞게 손봐야 하는데, 그것은 과적합입니다.
- **오류 처리가 아직 합의 전이라 거칩니다** (`docs/interfaces.md` 의 동기/비동기·오류 표현 합의 항목).
  - 근거 받기와 모델 호출은 잡는 범위가 넓어서, 그 안의 코드 버그도 `knowledge_error`, `model_error` 로 보입니다.
  - 호출 한도 초과(429)는 `model_error` 로만 보이고 `retry_after` 가 결과에 없어, 화면이 "몇 초 뒤 다시" 를 안내할 수 없습니다.
  - `error` 에 파이썬 오류 문장이 그대로 들어갈 수 있어 사용자에게 그대로 보여 주면 안 됩니다.
  - knowledge 가 비동기 함수로 정해지면 `'coroutine' object is not iterable` 로 `knowledge_error` 가 됩니다.
- **정답이 외부에서 검증되지 않았습니다.** `questions.json` 의 `must_cite_doc_ids` 는 RiftFlow 가 정한 값입니다.
  문서 내용은 Data Dragon 의 실제 값이지만, 어떤 문서가 그 질문의 정답인지는 판단입니다.
  롤을 직접 하는 사람이 검토해야 합니다.
- **500골드 미만 기본 재료(롱소드, 증폭의 고서, 루비 수정 등)는 하위 재료 목록에 나오지 않습니다.**
  fixture 가 500골드 이상 아이템만 담아 이름표에 없기 때문입니다. 하위 재료가 있는 165개 중 85개는 재료 이름이 일부 빠지고,
  49개는 재료 없이 `조합 비용` 만 나옵니다. 이름표에 없는 ID 는 숫자로 보이지 않게 일부러 뺍니다.
  `src/knowledge/` 수집기는 아이템을 가격 조건 없이 전부 저장하므로, 이름표를 그 데이터로 만들면 사라질 한계입니다.
- 근거 자료는 `knowledge.get_documents` 로 받습니다. 그 함수가 아직 없어서 지금은 `tests/fixtures/rag/` 의 JSON 을 읽는 대역을 씁니다.
  필드 이름(`kind`, `entity_id`, `version`, `content_hash`, `updated_at`)은 `src/knowledge/` 의 `records` 테이블과 맞춰 두었습니다.
  다만 `records` 에는 `text` 와 `fields` 가 없고 원본 JSON(`content`)만 있으므로,
  `get_documents` 가 이 문서 형식으로 풀어 주거나 rag 쪽에 변환 코드를 둬야 합니다. 어느 쪽이 할지는 합의가 필요합니다.

```powershell
python -m unittest discover -s tests/integration -p "test_rag*.py" -v
```

답변 문장은 검사하지 않습니다. 생성 결과는 매번 달라지기 때문입니다.

## 프롬프트

`prompt.py` 의 `SYSTEM` 이 챗봇 규약을 옮긴 곳입니다.
근거에만 의존할 것, 지어내지 말 것, 이유를 반드시 말할 것, `[근거 N]` 으로 표시할 것.

근거 블록마다 문서 ID 와 출처 URL 을 함께 넣습니다.
답변에 붙은 출처가 실제 문서를 가리키는지 확인할 수 있어야 하기 때문입니다.

질문 하나당 프롬프트는 대략 1,000~2,000자입니다. 넘치면 점수가 낮은 근거부터 버립니다.

## API 키

`.env` 의 `GEMINI_API_KEY` 를 환경변수로 읽습니다. 코드와 저장소에 키를 적지 않습니다.

공식 문서는 키를 URL 쿼리에 붙이라고 안내하지만, 그러면 접속 기록과 오류 로그에 키가 남습니다.
그래서 `x-goog-api-key` 헤더로 보냅니다.

## 대화 저장

**기본으로 켜져 있습니다.** 챗봇 규약이 "데이터는 전부 저장" 이라서입니다. 한 번만 빼려면 `--no-save` 를 줍니다.

`data/conversations.db` 에 남깁니다. `.gitignore` 가 `/data/*` 를 제외하므로 Git 에 올라가지 않습니다.
질문에 Riot ID 같은 개인정보가 섞일 수 있어 저장소에 올리면 안 됩니다.

토큰 칼럼은 "안 썼다" 와 "모른다" 를 구분합니다 (`docs/interfaces.md` 의 누락값과 0 구분).

| 경우 | 토큰 값 |
|---|---|
| Gemini 를 부르지 않음 (차단, 범위 밖, 근거 부족, `--call` 없이 프롬프트만) | `0` |
| 불러서 응답에 사용량이 옴 | 실제 값 |
| 부르려다 실패했거나 사용량이 오지 않음 | `null` |

`python -m rag history` 가 상태별 건수와 토큰 합계를 보여 줍니다. 모르는 값은 0 으로 채우지 않고 `null` 로 표시합니다.

챗봇 규약에 따라 **다른 챗봇 API 로 바꿀 수 있도록** 보낸 프롬프트까지 그대로 남깁니다.
`provider` 와 `model` 은 칼럼이라 Gemini 에 묶이지 않습니다.

막힌 질문도 남깁니다. 어떤 질문이 왜 막혔는지 봐야 안전장치를 고칠 수 있습니다.

## Gemini 호출에서 확인한 것

- 인증은 `x-goog-api-key` 헤더로 됩니다.
- 키가 틀리면 401 이 아니라 400 에 `API_KEY_INVALID` 로 옵니다.
- 모델이 붐비면 503 이 옵니다. 2초, 4초 뒤 두 번 더 시도합니다. 키와 모델 이름 오류는 다시 시도하지 않습니다.
- **Gemini 3 계열은 답변 전에 생각을 하고, 그 토큰이 `maxOutputTokens` 에 같이 들어갑니다.**
  1024 로 두었을 때 생각에 902 토큰을 쓰고 답변이 문장 중간에서 잘렸습니다. 지금은 4096 입니다.
- 근거에 가격을 넣지 않았더니 모델이 "가격 정보가 없다" 고 답했습니다. 지금은 가격과 조합식을 이름으로 넣습니다.
